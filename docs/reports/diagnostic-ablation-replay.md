# Diagnostic ablation and per-strategy selection report

Status: offline evidence only; no live or simulated account was changed and no order path was imported.

## Scope and provenance

This report runs the deterministic replay harness against every strategy family in the shared contract inventory. The 26-row fixture contains one buy and one sell decision for each of 13 strategies:

`orderbook`, `ml_enhanced_orderbook`, `ml`, `sma`, `ema`, `rsi`, `bollinger`, `macd`, `stochastic`, `fibonacci`, `atr`, `dca`, and `buy_and_hold`.

## Reproduction command and assumptions

```text
python tools/replay_diagnostic_ablation.py --input data/replay/diagnostic_ablation_fixture.jsonl --json-out docs/reports/diagnostic-ablation-example.json --markdown-out docs/reports/diagnostic-ablation-example.md
```

The harness uses the same cost model for all modes: fee rate `0.001` per side, spread `2.0` basis points per side, and slippage `1.0` basis points per side. The tested active-factor threshold is diagnostic score `0.60`. Modes are `disabled`, `report-only`, and `factored`; omitted `diagnostic_score` is unavailable, never zero. A meaningful regression is any new block or an expectancy change of at least 10% with a minimum absolute change of `0.001` from report-only to factored.

## Aggregate replay evidence

Every mode produced 26 strategy-direction groups (13 strategies x buy/sell), and all 26 fixture decisions were evaluated in disabled and report-only modes. Factored mode executed 13 and blocked 13. Each mode observed the same four unavailable diagnostics. The raw JSON and Markdown artifacts contain average win, average loss, net expectancy, profit factor, maximum drawdown, trade frequency, buy/sell direction, blocked executions, and unavailable counts for every group.

| Mode | Groups | Executed trades | Blocked executions | Unavailable diagnostics |
|---|---:|---:|---:|---:|
| disabled | 26 | 26 | 0 | 4 |
| report-only | 26 | 26 | 0 | 4 |
| factored (threshold 0.60) | 26 | 13 | 13 | 4 |

The factored run reports 13 meaningful regressions: every strategy's sell side is blocked because the fixture contains either a score below `0.60` (`0.42`) or an unavailable diagnostic. This is the expected fail-closed signal, but it is not evidence that active factoring improves the objective on this one-row-per-direction fixture. No strategy therefore qualifies for unconditional active factoring or a threshold/weight change from this experiment.

## Disposition for every strategy

The selected offline disposition is `report-only` for all 13 strategy families. This preserves the disabled/report-only objective and trade frequency in the supplied evidence while avoiding promotion of an unvalidated threshold. The explicit live exception is mandatory: if a required diagnostic is unavailable or invalid, live execution remains blocked/fail-closed; report-only here means the diagnostic is observable in replay/reporting, not that live safety gates are bypassed.

## Safety and follow-up boundary

- The replay output records `offline_only: true` and `live_orders_enabled: false`; no exchange, account, or order module is imported.
- The factored behavior demonstrates the required unavailable/low-score blocking semantics in both directions. It must not be interpreted as authorization to change live defaults.
- This fixture cannot establish strategy-specific weights, sizing, exits, or production thresholds. A larger timestamped dataset with train/validation/holdout separation is required before selecting active factoring.
- No implementation defect was exposed in the harness run. The follow-up integration lane should not activate these synthetic threshold results; it should preserve report-only/unavailable declarations and add production-data evidence before any live-affecting rule is proposed.
